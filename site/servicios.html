Servicios

Festa tiene ocho microservicios de negocio, un gateway y una base de datos por servicio. Ningún servicio lee la base de otro: se comunican por REST a través del gateway (llamadas que esperan respuesta) y por eventos en RabbitMQ (avisos que no esperan respuesta). Esta página describe cada servicio en su versión actual.

Resumen

Gateway (festa-gateway)

Kong 3.9 en modo DB-less: la configuración es un archivo declarativo, no una base de datos. Valida el JWT con la llave pública de auth-service, aplica límites por token o por IP y reenvía cada ruta al servicio que la atiende.

Ruta pública Servicio Token Límite
POST /api/auth/* (registro, inicio de sesión, Google, renovación, cierre) auth-service No 30/min y 300/h por IP
/api/auth/me*, /api/auth/admin/* auth-service Sí 120/min por token
/api/users, /api/merchants, /api/reports user-service Sí 120/min por token
/api/events event-service Sí 300/min por token
/api/bookings booking-service Sí 300/min por token
/api/payments payment-service Sí 30/min por token
POST /webhooks/wompi payment-service (valida la firma de Wompi) No 120/min por IP
/api/ai ai-service Sí 30/min por token
/api/notifications notification-service Sí 120/min por token
/api/analytics analytics-service Sí 120/min por token

Kong reenvía el prefijo /api tal cual lo quita: /api/events/... llega a event-service como /events/....

Autenticación (festa-auth-service)

Tecnología: Spring Boot 3.5.16, PostgreSQL, RabbitMQ. Base: auth_db.

Tablas: accounts, refresh_tokens, outbox, processed_events.

Método Ruta Descripción
POST /api/auth/register Registro con correo
POST /api/auth/login Inicio de sesión. Bloquea la cuenta tras 5 intentos fallidos
POST /api/auth/google Inicio de sesión con Google
POST /api/auth/refresh Renueva el token de acceso
POST /api/auth/logout Cierra la sesión
GET /api/auth/me Cuenta de la sesión actual
PUT /api/auth/me/password Cambia la contraseña
DELETE /api/auth/me Borra la cuenta
GET /api/auth/admin/accounts/{id} Consulta una cuenta (admin)
PATCH /api/auth/admin/accounts/{id}/role Cambia el rol (admin)
  • Publica: account.registered, account.display_name_set, account.role_changed, account.deleted.
  • Consume: moderation.user_suspended y moderation.user_reinstated, para suspender o reactivar el acceso.

Compras (festa-payment-service)

Tecnología: Node.js 20, Express 5, PostgreSQL, RabbitMQ, Wompi. Base: payment_db.

Tablas: event_projection, merchants, orders, payouts, wompi_webhooks, payment_discrepancies, closed_events, deleted_accounts, outbox, processed_events.

Método Ruta Descripción
GET /api/payments/events/{id}/quote Precio y comisión de Wompi, antes de comprar
POST /api/payments/orders Crear una orden. Requiere Idempotency-Key
GET /api/payments/orders/mine Mis órdenes
GET /api/payments/orders/{id} Una orden
GET /api/payments/merchants/me/summary Resumen de ventas y liquidaciones del comercio
POST /webhooks/wompi Confirmación de Wompi. Valida la firma antes de procesar
GET / POST /api/payments/admin/refunds, /api/payments/admin/payouts y acciones sobre órdenes Reembolsos y liquidaciones (admin)

La simulación del pago (POST /api/payments/orders/{id}/simulate) solo responde si PAYMENTS_ALLOW_SIMULATION=true y el entorno no es producción. Sirve para probar el flujo completo sin la pasarela real.

  • Publica: order.created, order.approved, order.failed, order.expired, order.refund_requested, order.refunded, payout.recorded.
  • Consume: event.published, event.updated, event.cancelled, event.expired, merchant.verified, merchant.updated, account.deleted.

Chat y descripciones con IA (festa-ai-service)

Tecnología: Python, FastAPI, Redis (límite por minuto), MongoDB, Gemini como modelo. Base: MongoDB (descripciones y sesiones de chat).

Método Ruta Descripción
POST /api/ai/chat Responde con eventos reales. Solo recomienda ids que existen
GET /api/ai/chat/sessions/{id} Historial de una sesión
DELETE /api/ai/chat/history Borra el historial propio
POST /api/ai/descriptions Genera y guarda la descripción de un evento

El límite es de 10 solicitudes de chat y 5 de descripción por minuto y por usuario. No acota el gasto diario.

  • Publica: description.generated, recommendation.served.
  • Consume: event.published, event.updated, event.cancelled, event.expired, event.sold_out, merchant.updated, location_consent.granted, location_consent.revoked, profile.updated, account.deleted.

Notificaciones (festa-notification-service)

Tecnología: Node.js 20, Express 5, MongoDB, RabbitMQ, Firebase Cloud Messaging (push). Base: MongoDB.

Método Ruta Descripción
POST / DELETE /api/notifications/devices Registrar o quitar un dispositivo
PUT / DELETE /api/notifications/location Ubicación para avisos cercanos, solo con consentimiento
GET /api/notifications Bandeja de notificaciones
GET /api/notifications/unread-count Cantidad sin leer
POST /api/notifications/{id}/read y /read-all Marcar como leídas
  • Publica: push.sent.
  • Consume: los eventos de publicación, asistencia, pagos, comercios, moderación, reportes y cuentas. Con ellos arma la bandeja y los recordatorios.

Estados

Orden de compra: PENDING → APPROVED (pago aprobado), DECLINED, ERROR o VOIDED (anulada); PENDING → EXPIRED si vence el cupo retenido; APPROVED → REFUND_REQUESTED → REFUNDED.

Evento: published puede pasar a hidden (moderación), cancelled o expired.

Pase: valid → used (escaneado en la entrada) o revoked (orden reembolsada). Un pase used o revoked no lleva QR.

Asistencia: rsvp (gratis) o ticket (boleta comprada). Se confirma o se cancela.
